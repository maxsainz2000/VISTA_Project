## [2026-06-01] claude-code | added error-fix | Owner login threw `UnauthorizedWriteException` on `Acc_VatReturns` — the read-only Owner KPI dashboard computed the "VAT Payable" tile via `VatPayableKpiProvider`, which called `IVatReportingService.GenerateMonthlyVatReturnAsync`/`GenerateNonVatPercentageTaxAsync`; those `Add` + `SaveChangesAsync` a VatReturn, and `RoleGuardInterceptor` (OWASP DA5, correct) rejected the write. A write-on-read defect, not an interceptor bug. Fix: added non-persisting `PreviewMonthlyVatReturnAsync`/`PreviewNonVatPercentageTaxAsync` to the service (reuse `CollectLedgerDataAsync`+`BuildVatReturn`, no `Add`/`SaveChanges`) and pointed the KPI provider at them; `Generate*` unchanged for the Manager-initiated `VatReturnViewModel.GenerateAsync` path. See `errors/owner-readonly-kpi-write-on-read.md`.

## [2026-05-29] antigravity | added error-fix | SQLite-dialect leakage in raw SQL after pivot. Raw SQL written with SQLite-specific features (datetime helper, INSERT OR REPLACE) and double quotes failed on centralized MariaDB without ANSI_QUOTES. Fix: updated raw statements to use backticks, DATE_ADD/NOW(6) native datetime functions, and ON DUPLICATE KEY UPDATE. See `errors/mariadb-raw-sql-sqlite-dialect-leakage.md`.

## [2026-05-29] claude-code | added error-fix | Stock Dashboard Avg Cost / FIFO Cost columns rendered blank for products that had stock. The DataGrid binds to a flattened VM row type `ProductRowItem`, which was missing `AverageUnitCost`/`FifoOldestUnitCost` and whose `ProductSummaryDto`→row projection never copied them; WPF resolved the column bindings to a non-existent path and silently left the cells empty. Service computation was correct. Fix: add the two properties to `ProductRowItem` + map them. Lesson: DTO→bindable-row flattening makes adding a DTO field a 3-edit change (DTO, row class, mapping). See `errors/wpf-datagrid-binds-vm-rowitem-missing-property-blank-cell.md`.

## [2026-05-29] claude-code | added error-fix | Goods Receiving "Confirm Receipt" crashed with "Unknown column 'InputVat' in 'field list'" — the central `Acc_ExpenseRecords`/`Acc_RevenueRecords` tables (created by `0001_initial_schema.sql`) were never given the six BIR VAT columns that ACC-10 added to the entities via `LedgerVatExtensions.vb` partial classes; those columns had only ever existed in the SQLite-era EF migration `20260510100000_AddVatLedgerColumns`, which was orphaned by the 2026-05-28 MariaDB pivot. EF maps all six by convention and emits them in every INSERT, so even the non-VAT `GoodsReceivedAccountingHandler` failed. Fix: new idempotent `Migrations/Central/AddAccVatLedgerColumns.sql` (`ADD COLUMN IF NOT EXISTS`). See `errors/efcore-vat-ledger-columns-missing-central-schema.md`.

## [2026-05-29] antigravity | added error-fix | Soft-delete vs database unique-key collision — soft deletes leave rows in the DB and EF queries hide them via global filters, but unique indexes span all rows causing Duplicate entry crashes on save. Resolved using Policy A (sequence skipping) and Policy B (friendly error checks or auto-restoration). See `errors/efcore-softdelete-unique-key-collision.md`.

## [2026-05-29] claude-code | added error-fix | PO "Save Draft" crashed with "Unknown column 'RowVersion'" — `AuditableEntity` inherits `ConcurrencyAwareEntity`, so every auditable entity gets a `RowVersion` property EF maps by convention; append-only child tables (e.g. `Pur_PurchaseOrderLines`) have no such column. Fix: `builder.Ignore(Function(l) l.RowVersion)` in the line config. See `errors/efcore-inherited-rowversion-unmapped-column.md`. Latent across other child tables (GoodsReceiptLines, SalesTransactionLines, CreditPayments).
