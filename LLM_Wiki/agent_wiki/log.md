## [2026-06-03] claude-code | added antipattern | UX-03 implicit control styles threw `XamlParseException` → `ArgumentNullException (Parameter 'property')` at `Setter.Property`, line 82 of `Themes/Controls.xaml`. The implicit `ScrollBar` style's `Orientation=Horizontal` trigger tried to swap the `Track`'s children with `<Setter TargetName="PART_Track" Property="DecreaseRepeatButton">` (and `IncreaseRepeatButton`, `Thumb`). Those are **plain CLR properties, not DependencyProperties**, so a `<Setter>` cannot target them — the property-system lookup returns null and throws when the style is *sealed at runtime*. Build was 0/0 (setter-target validity is not a compile check) and it detonated on the Login `TextBox` (its template hosts a `ScrollViewer` → `ScrollBar`). Fix: author two complete `ControlTemplate`s (vertical default + horizontal) and swap the whole `Template` (a real DP) in a `Style.Trigger` instead of mutating Track children. Same "compiles clean / fails at style realization" class as the brush-into-`Color` trap. See `antipatterns/wpf-setter-targets-clr-property-not-dependencyproperty.md`.

## [2026-06-03] claude-code | added antipattern | UX-02 shell reskin threw `XamlParseException` → `InvalidOperationException: '#FFF5F5F7' is not a valid value for property 'Color'` at view load. `ActivityRail.xaml` and `ModuleDetailPanel.xaml` both declared `<SolidColorBrush x:Key="HoverBackgroundBrush" Color="{DynamicResource TextPrimaryBrush}" Opacity="0.06"/>` — feeding a `SolidColorBrush` token into the `Color`-typed property. Type mismatch is invisible to the compiler (build was 0/0) and only realizes at dictionary load; surfaced only in Dark because the app boots the persisted Dark palette (`#F5F5F7` = Dark `TextPrimaryBrush`). Fix: define `HoverBackgroundBrush` as a real semi-transparent brush per palette (Light `#1D1D1F`@0.06, Dark `#FFFFFF`@0.08), delete the broken local copies, consume via `{DynamicResource}`. A semi-transparent variant of a themed color is not derivable in markup — author it per palette. See `antipatterns/wpf-dynamicresource-brush-into-color-property.md`.

## [2026-06-02] claude-code | added error-fix | `SslMode=None` crashes the app right after a successful Owner login. The app uses two MySQL stacks on one connection string: raw `MySqlConnector` (auth/login — `MySqlSslMode` has `None`) and Oracle `MySql.EntityFrameworkCore`/`UseMySQL` (module DbContexts — enum has `Disabled`, NOT `None`). `None` parses for login but Oracle's `MySqlConnectionStringBuilder` throws `ArgumentException: Requested value 'None' was not found` at the first DbContext build (dashboard nav, post-login) → "app closes after I log in". Fix: `SslMode=Preferred` (accepted by both; plaintext vs non-TLS server). Never `None` (Oracle rejects) or `Disabled` (MySqlConnector rejects) while both stacks share the string. See `errors/sslmode-none-invalid-oracle-mysql-efcore-provider.md`. Also noted: non-fatal Owner-dashboard DbContext-concurrency error (`A second operation was started on this context instance`) on initial concurrent KPI load — recovers on refresh; fix via `IDbContextFactory` per query (future code session).

## [2026-06-02] claude-code | added error-fix | Read-only Owner remote client (SELECT-only `merchsys_owner`) crashes at startup with "VISTA — Fatal / Cannot initialize database schema". `MariaDbSchemaInitializer.Initialize` runs on every launch and its first statement `CREATE TABLE IF NOT EXISTS __SchemaMigrations` is denied with `ERROR 1142` — MariaDB checks the `CREATE` privilege *before* `IF NOT EXISTS`, so it fails even though the table exists, and this is *before* login so no auth grant helps. Second blocker: `AuthenticationService.ClearFailedAttempts` does `UPDATE Sys_UserAccounts` on successful auth (denied to SELECT-only). Found during Phase 1 Tailscale Owner acceptance test. Remediation deferred (operator chose manual verification): minimal `UPDATE` grant on `Sys_UserAccounts` for login bookkeeping + gate the startup bootstrap for read-only clients (config flag, NOT a DDL grant). See `errors/readonly-client-blocked-by-startup-ddl-bootstrap.md` and `Operator/PHASE-1-tailscale-owner-acceptance-2026-06-02.md`.

## [2026-06-01] claude-code | added error-fix | Owner login threw `UnauthorizedWriteException` on `Acc_VatReturns` — the read-only Owner KPI dashboard computed the "VAT Payable" tile via `VatPayableKpiProvider`, which called `IVatReportingService.GenerateMonthlyVatReturnAsync`/`GenerateNonVatPercentageTaxAsync`; those `Add` + `SaveChangesAsync` a VatReturn, and `RoleGuardInterceptor` (OWASP DA5, correct) rejected the write. See `errors/owner-readonly-kpi-write-on-read.md`.

## [2026-05-29] antigravity | added error-fix | SQLite-dialect leakage in raw SQL after pivot. ## [2026-05-29] claude-code | added error-fix | Stock Dashboard Avg Cost / FIFO Cost columns rendered blank for products that had stock. ## [2026-05-29] claude-code | added error-fix | Goods Receiving "Confirm Receipt" crashed with "Unknown column 'InputVat' in 'field list'" — the central `Acc_ExpenseRecords`/`Acc_RevenueRecords` tables (created by `0001_initial_schema.sql`) were never given the six BIR VAT columns that ACC-10 added to the entities via `LedgerVatExtensions.vb` partial classes; those columns had only ever existed in the SQLite-era EF migration `20260510100000_AddVatLedgerColumns`, which was orphaned by the 2026-05-28 MariaDB pivot.
